# RETUNE v0.4 iOS Alpha Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a directly installable iPhone alpha that can play a reference tone, capture voice, estimate pitch, score same-note recall, and train reference-only interval generation for half/whole steps and major thirds.

**Architecture:** Native SwiftUI app with AVAudioSession / AVAudioEngine for playback and microphone capture. Audio detection, musical math, attempt analysis, and training state are isolated from SwiftUI so they can be unit-tested independently. The initial alpha deliberately stops at the first three proof slices from the v0.4 design: measurement, single-note recall, and interval generation.

**Tech Stack:** Swift 5.10+, SwiftUI, AVFoundation, Accelerate, SwiftData, XCTest, Xcode 16+, iOS 17+, XcodeGen for reproducible project generation.

**Spec:** `docs/superpowers/specs/2026-09-09-retune-v0.4-ios-design.md`

## Global Constraints

- Native iOS app; no PWA implementation for new work.
- iOS 17+ and iPhone-first UI.
- Initial use is Xcode direct installation to the user's iPhone; App Store publication is not required.
- No backend, authentication, cloud sync, subscription, AI chat, copyrighted-song ingestion, or physiological vocal diagnosis in this alpha.
- Reference audio must stop before scored recording.
- A4=440 Hz equal temperament is the reference tuning.
- Low-confidence / low-RMS frames are excluded rather than scored as wrong.
- Training UI follows `Listen → Recall → Sing → Check`.
- During reference-only interval exercises, realtime correction must not reveal the target closely enough for visual steering.
- The current RETUNE design direction is preserved: dark-first, mint/cyan accent, restrained glass, glow only for active states, one primary action per screen.

- [ ] **Step 1: Write a sine-wave helper in the test file**

```swift
func sine(frequency: Double, sampleRate: Double = 44_100, count: Int = 4096) -> [Float] {
    (0..<count).map { i in
        Float(sin(2 * Double.pi * frequency * Double(i) / sampleRate))
    }
}
```

- [ ] **Step 2: Write failing detector tests**

- [ ] **Step 3: Run and verify failure**

- [ ] **Step 4: Implement normalized autocorrelation**

Use a vocal range search roughly 80–1000 Hz. Compute candidate lag correlations, select the strongest peak above confidence threshold, and refine the lag using parabolic interpolation around the peak. Keep this first implementation intentionally isolated behind `PitchDetector`.

## Verification Before Calling This Alpha Usable

Run the complete test suite:

```bash
xcodegen generate
xcodebuild test -project RETUNE.xcodeproj -scheme RETUNE -destination 'platform=iOS Simulator,name=iPhone 16'
```

Then perform the following on the user's real iPhone:

1. Reference A4 is audibly correct.
2. Sustained tone detection does not repeatedly flip an octave.
3. Clean sustained notes are typically within ±10 cents of a known tuner/reference under quiet conditions.
4. Low-volume breath/noise does not appear as a confident note.
5. Same-note model-heard and delayed-recall attempts save separate results.
6. Major-third model-heard vs reference-only results can differ and are stored independently.
7. A +400-cent target produced at +450 cents reports approximately +50 cents wide.
8. During Recall/Sing, the UI does not visually reveal the target pitch correction.
9. `今日の3分` can be completed without selecting exercises manually.
10. No physiological diagnosis copy appears anywhere in the alpha.
